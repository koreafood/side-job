# 아키텍처 개요 (ADR 포함)

이 문서는 프로젝트의 구조와 기술 선택 이유를 초보자도 이해할 수 있도록 설명합니다. 내용은 현재 코드와 설정 파일을 기준으로 작성되었습니다.

## 1. 시스템 한눈에 보기

이 프로젝트는 하나의 저장소 안에 프론트엔드와 백엔드가 함께 들어 있는 구조입니다.

- 프론트엔드: Vue 3 + Vite 기반 SPA
- 백엔드: FastAPI + SQLModel
- 데이터베이스: SQLite
- 파일 저장소: 로컬 디렉터리(`/api/uploads`)
- 배포: Vercel 설정 + Proxmox/서버 배포 스크립트

## 2. 구성 요소별 역할

### 2.1 프론트엔드 (Vue 3)

- 사용자 화면: 홈, 상품 상세, 장바구니, 주문 조회 등
- 관리자 화면: 상품 등록/수정, 주문 관리, 제작 단계 관리
- 상태 관리: composables 기반(`useCartStore`, `useAdminStore`)
- 라우팅: Vue Router로 경로 분기 및 관리자 권한 가드 처리

### 2.2 백엔드 (FastAPI)

- REST API 제공
- SQLModel로 DB CRUD 처리
- 관리자 로그인 세션 발급(쿠키 기반)
- 파일 업로드 및 정적 파일 제공(`/uploads`)

### 2.3 데이터베이스 (SQLite)

SQLModel 모델 정의를 기반으로 테이블이 생성됩니다. 마이그레이션은 `init_db()`에서 필요한 컬럼을 확인 후 `ALTER TABLE`로 보완합니다.

### 2.4 파일 저장소

이미지 업로드 파일은 `api/uploads` 폴더에 저장되며, `/uploads/*` 경로로 접근합니다. 배포 환경(Vercel)에서는 `/tmp/uploads`를 사용합니다.

## 3. 데이터 흐름 요약

### 3.1 일반 사용자 흐름

1. 홈 화면에서 상품 목록 조회  
2. 상품 상세에서 장바구니 담기  
3. 장바구니에서 주문 생성  
4. 주문 상세에서 제작 단계 및 리뷰 확인

### 3.2 관리자 흐름

1. 관리자 로그인 → 쿠키 세션 생성  
2. 상품 등록/수정/삭제  
3. 주문 상태 변경  
4. 제작 단계(메모/사진) 추가

## 4. 주요 기술 선택 이유

### 4.1 Vue 3 + Vite

- 빠른 개발 서버와 빌드 속도
- 컴포지션 API를 통한 로직 분리 용이
- 타입스크립트와 자연스럽게 결합

### 4.2 FastAPI

- Python 기반으로 간단하게 API 구성 가능
- Pydantic 기반의 입력/출력 검증이 쉬움
- 문서화(OpenAPI) 확장이 용이함

### 4.3 SQLModel + SQLite

- 개발/데모 환경에서 가볍게 운영 가능
- SQLModel은 Pydantic + SQLAlchemy 통합으로 타입 안정성 확보
- 초기 구축이 빠르며 구조가 단순함

### 4.4 로컬 파일 업로드

- 외부 스토리지 없이도 이미지 관리 가능
- 구현이 단순하고 배포 옵션에 따라 확장 가능

## 5. 인증/권한 구조

- 관리자 로그인 시 백엔드에서 쿠키(`is_admin=1`) 발급
- 프론트 라우터 가드가 로컬 스토리지 `isAdmin` 플래그로 접근 제어
- 현재 서버 측 관리자 API에 별도 권한 검증 로직은 없음  
  (보안 강화를 위해 서버 측 인증 검증 추가가 필요)

## 6. 환경 변수 및 실행 환경

- `API_ORIGIN`: 절대 URL 생성 및 업로드 URL 정규화에 사용
- `VERCEL=1`: Vercel 환경에서 DB/업로드 경로를 `/tmp`로 전환

## 7. 주요 ADR (Architecture Decision Records)

### ADR-001: 프론트/백엔드 단일 레포 구성

- **결정**: 하나의 저장소에 frontend와 backend 공존
- **이유**: 개발 편의성, 배포 단순화
- **영향**: 패키지 관리 및 빌드/배포 과정에서 경로 분리가 필요

### ADR-002: FastAPI + SQLModel + SQLite 사용

- **결정**: Python 기반 FastAPI와 SQLModel, SQLite 선택
- **이유**: 빠른 개발과 간단한 배포
- **영향**: 대규모 확장 시 DB 교체 및 마이그레이션 필요 가능성

### ADR-003: 관리자 인증을 쿠키 기반으로 처리

- **결정**: 관리자 로그인 성공 시 `is_admin` 쿠키 발급
- **이유**: 복잡한 인증 시스템 없이 데모 환경에 적합
- **영향**: 현재는 보안이 약하며 운영 환경에서는 개선 필요

### ADR-004: 업로드 파일 로컬 저장

- **결정**: 파일을 `/uploads` 디렉터리에 저장
- **이유**: 구현 단순성
- **영향**: 서버 장애/스케일아웃에 취약 → 스토리지 분리 고려 필요

### ADR-005: Vercel + 서버 배포 병행

- **결정**: Vercel 설정과 Proxmox 배포 문서를 병행
- **이유**: 개발/배포 옵션을 유연하게 확보
- **영향**: 환경별 경로/설정 차이 관리 필요

## 8. 향후 개선 포인트

- 관리자 API 서버 측 인증/인가 강화
- DB 마이그레이션 도구(Alembic 등) 도입
- 이미지 스토리지 S3 등 외부 스토리지로 분리
- 로깅/모니터링 정책 문서화 및 적용
